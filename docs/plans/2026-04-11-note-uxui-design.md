# Note UX/UI Redesign

**Date:** 2026-04-11

**Goal:** `notes` 리스트와 `note` 상세를 검색 유입 중심의 개인 기술 블로그 경험으로 재설계한다.

## Product Direction

이 사이트의 주 유입은 검색이다. 사용자는 대체로 특정 글 하나를 읽기 위해 들어오고, 그 뒤에 같은 주제의 다른 글로 이동한다.

따라서 첫 인상은 `지식 아카이브`가 아니라 `개인 기술 블로그`여야 한다.

- 글이 화면의 주인공이어야 한다
- 카테고리/태그/목차는 보조 탐색이어야 한다
- 내부 탐색은 유지하되 읽기 흐름을 방해하면 안 된다

## Notes List

### Intent

리스트는 “문서 인덱스”처럼 보이기보다 “블로그 포스트 목록”처럼 보여야 한다.

### Layout

- 왼쪽: 얇은 카테고리 바
- 가운데: 제목과 요약 중심의 세로 포스트 목록
- 썸네일: 기본 전제에서 제외

카테고리 바는 유지하되, 지금처럼 도구형 트리 UI가 아니라 블로그형 탐색 레일로 바꾼다.

### Left Rail

왼쪽 카테고리 바 상단에는 짧은 탐색 헤더를 둔다.

예시:

- `Browse topics`
- 짧은 설명 한 줄
- 그 아래 카테고리 목록

핵심은 “복잡한 필터 도구”처럼 보이지 않게 만드는 것이다.

### Post List

각 항목은 다음 정보 위계로 구성한다.

1. 제목
2. 짧은 요약
3. 날짜
4. 카테고리
5. 태그(있다면 약하게)

썸네일이 없더라도 완성도가 나와야 하므로, 타이포와 간격으로 밀도를 조절한다.

## Note Detail

### Intent

상세는 구조화된 문서 느낌보다 “읽는 글” 느낌이 우선이어야 한다.

### Layout

- 왼쪽: 카테고리 바 유지
- 가운데: 본문 중심 컬럼
- 오른쪽: `On this page`

`On this page`는 유지하지만, 본문과 같은 강도로 경쟁하지 않도록 오른쪽 레일에 둔다.

### Header

상세 상단은 다음 정도만 남긴다.

- breadcrumb
- 제목
- 날짜 / 카테고리
- 태그

여기서 제목과 본문 진입이 가장 중요하다.

### Right Rail

오른쪽 레일의 우선순위는 명확하다.

1. `On this page`
2. `Related`
3. `Backlinks`

`Related`와 `Backlinks`는 유지하되, `On this page`보다 한 단계 약하게 처리한다.

## Mobile

모바일은 단일 컬럼이 기본이다.

- 카테고리 바는 본문보다 앞쪽에 노출
- `On this page`는 본문 바로 뒤에 노출
- 댓글이나 기타 하단 요소보다 먼저 보여야 함

핵심은 탐색을 숨기는 것이 아니라, 읽기 흐름 안에 자연스럽게 재배치하는 것이다.

## Visual Principles

- 썸네일 없이도 완성도가 나와야 한다
- 글 제목과 본문 진입이 가장 먼저 보여야 한다
- 카테고리 바는 유지하되 시각적 존재감은 낮춘다
- 오른쪽 목차는 유지하되 본문을 압도하지 않는다
- 전체 톤은 “정리 잘 된 개인 기술 블로그”에 가깝게 만든다

## Scope

이번 작업은 다음 범위에 한정한다.

- `notes` 리스트 레이아웃 재설계
- `note` 상세 레이아웃 재설계
- 카테고리 바의 톤과 정보 위계 재정리
- 오른쪽 `On this page`와 보조 정보 재정리
- 모바일 순서 재설계

이번 작업에서 제외한다.

- 콘텐츠 모델 변경
- 검색 기능 변경
- 댓글 기능 변경
- 관련 노트 계산 로직 변경
