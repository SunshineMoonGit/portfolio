# Page Structure

## 라우팅

```
/                   메인 포트폴리오 페이지
/notes              노트 목록
/notes/[slug]       노트 상세
```

---

## / — 메인 페이지

### 목적

첫 인상은 포트폴리오. "이 사람이 누구고 무엇을 만드는가"를 빠르게 전달한다.

### 섹션 구성

```
Hero
  이름, 한 줄 소개, 관심 분야

Projects
  대표 프로젝트 카드 (2~4개)
  각 카드: 이름, 설명, 사용 기술, 링크

Now
  현재 공부 중인 주제 / 진행 중인 작업
  최근 노트 3~5개 미리보기

Notes
  전체 노트 아카이브 진입점 링크
```

### 필요한 데이터

| 출처                    | 데이터                              |
|-------------------------|-------------------------------------|
| `GET /api/profile`      | 이름, 소개, 관심 분야, 프로젝트 목록 |
| `GET /api/notes?limit=5` | 최근 노트 목록                      |

---

## /notes — 노트 목록 페이지

### 목적

전체 공개 노트를 탐색한다.

### UI 구성

- 노트 카드 목록 (제목, 카테고리, 태그, 날짜, 요약)
- 카테고리 필터 (선택 시 해당 카테고리만 표시)
- 정렬: `date` 내림차순 (고정)

### 필요한 데이터

| 출처                              | 데이터           |
|-----------------------------------|------------------|
| `GET /api/notes?category=<value>` | 필터링된 노트 목록 |

---

## /notes/[slug] — 노트 상세 페이지

### 목적

단일 노트의 전체 내용을 읽는다.

### UI 구성

- 제목, 날짜, 카테고리, 태그
- Markdown 본문 렌더링
- 이전/다음 노트 네비게이션 (date 기준 인접 노트)

### 필요한 데이터

| 출처                        | 데이터                   |
|-----------------------------|--------------------------|
| `GET /api/notes/<slug>`     | 노트 전체 (content 포함) |

이전/다음 노트는 API 응답에 `prev` / `next` 필드로 포함한다.

---

## 데이터 접근 패턴

SvelteKit `+page.server.ts`에서 FastAPI를 호출한다.  
파일시스템 직접 접근 없음. 모든 데이터는 API를 통해서만 읽는다.

```
/                → GET /api/profile + GET /api/notes?limit=5
/notes           → GET /api/notes
/notes/[slug]    → GET /api/notes/<slug>
```

렌더링 방식: SSR (서버 사이드 렌더링).  
이유: ingest 후 재빌드 없이 즉시 반영되어야 하기 때문.
